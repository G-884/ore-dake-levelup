# 俺だけレベルアップ v0.1

自宅トレーニングを記録して EXP を貯め、レベルと5ステータス（STR / VIT / END / AGI / DEX）を育てる個人用 PWA。
サーバー・ログイン・クラウドDBは不要。データは端末のブラウザ内（localStorage）に保存されます。

---

## 1. スマホで使えるようにする

### 方法A: どこかに置いて開く（推奨・PWAとして完全に動作）

このフォルダの中身をそのまま HTTPS のどこかに置いて、`index.html` を開くだけです。ビルド作業はありません。

よく使われる置き場所の例:

- **GitHub Pages** — リポジトリを作って中身を push し、Settings → Pages で公開
- **Netlify Drop** — https://app.netlify.com/drop にフォルダをドラッグするだけ
- **Cloudflare Pages / Vercel** — 同様に静的サイトとしてデプロイ

公開できたら、スマホのブラウザでそのURLを開き、

- iPhone (Safari): 共有ボタン → 「ホーム画面に追加」
- Android (Chrome): メニュー → 「アプリをインストール」／「ホーム画面に追加」

これで全画面のアプリとして起動し、オフラインでも動きます。

> ⚠️ `file://` で直接開いた場合、Service Worker とホーム画面追加は動作しません（ブラウザの仕様）。
> アプリ自体（記録・保存）は動きますが、PWAとして使うには上記のホスティングが必要です。

### 方法B: 単一HTMLファイルで使う

`ore_dake_levelup_single.html` は、CSS・JavaScript をすべて1ファイルに埋め込んだ版です。
ファイルを1つ配るだけで動きます（Service Worker は無効）。動作確認用・予備用。

## 2. ファイル構成

```
index.html            画面の器（スクリプトの読み込みのみ）
manifest.json         PWA設定
sw.js                 Service Worker（オフラインキャッシュのみ。保存データには触れない）
icons/                アプリアイコン
css/style.css         スタイル

js/config.js          定数・初期設定値・初期種目マスタ   ← バランス調整はまずここ
js/utils.js           日付・数値・ID などの汎用処理
js/schema.js          保存データの形と migration        ← データ構造を変えるときはここ
js/storage.js         保存場所（localStorage / メモリ）  ← IndexedDB化するならここだけ差し替え
js/calculator.js      計算式（Load / EXP / Lv / 成長 / ストリーク / PB）
js/gamestate.js       記録からゲーム状態を集計する
js/repository.js      データアクセス層（UIはここだけを呼ぶ）
js/ui/*.js            画面
js/app.js             ルーティング・起動・復旧画面
```

依存の向きは一方向です。

```
UI  →  Repository  →  Storage
            ↓
       Calculator / GameState / Schema
```

UI から localStorage を直接触っている箇所はありません。

## 3. データが消えないようにしている仕組み

- 保存データには必ず `schemaVersion` が入っています。
- 起動時にバージョンを確認し、古ければ `js/schema.js` の `MIGRATIONS` で自動変換します。
- **migration の前に必ず自動バックアップを作成**します（最大5件保持）。
- migration に失敗した場合、**元データには一切書き込まず**、復旧画面を表示します。
- 保存データが壊れていた場合も、**勝手に初期化や上書きはしません**。復旧画面からバックアップを選べます。
- 既存データを消して新形式で作り直す処理は、コード上どこにもありません。

### 将来スキーマを変更するときの手順

1. `js/schema.js` の `MIGRATIONS` に `1: function (data) { ... return v2形式; }` を追加
2. `js/config.js` の `CURRENT_SCHEMA_VERSION` を `2` にする
3. 変換関数の中では、必ず既存の記録を引き継ぐ（作り直さない）

これだけで、旧データを持っている端末は起動時に自動で新形式へ移行します。

## 4. ゲームの計算

すべて `js/calculator.js` にまとまっています。UI側に計算式は書かれていません。
係数は `js/config.js` の初期値 → 保存データの `settings` / `activityMasters` に入り、**アプリ内の設定画面から変更できます**。

| 種類 | 式 |
|---|---|
| 自重（回数） | `Load = 負荷係数 × √(回数)` |
| 握力（重量×回数） | `Load = 負荷係数 × √(重量 × 回数)` |
| 柔軟（分） | `Load = 負荷係数 × √(分)` |
| ランニング | `Load = 距離 × 負荷係数 × √(基準ペース ÷ 実ペース)` |
| EXP | `Load × EXP係数 × 倍率 × (1 + ストリークボーナス + PBボーナス)` |
| レベル | `Lv = floor(√(累積EXP ÷ 40)) + 1` |
| ステータス成長 | `Load × 成長係数 × 配分率 × √(10 ÷ 現在値)` |

### 初期バランス

| 種目 | 例 | Load |
|---|---|---:|
| 腕立て伏せ | 100回 | 40.0 |
| スクワット | 100回 | 36.0 |
| 腹筋 | 100回 | 32.0 |
| 懸垂 | 10回 / 25回 | 25.3 / 40.0 |
| 握力 | 40kg × 30回 | 20.8 |
| 柔軟 | 10分 | 14.2 |
| ランニング | 5km (6分/km) | 50.0 |

週3回・毎回「腕立て100 / スクワット100 / 腹筋100」を1年続けた場合の着地点:

```
累積EXP 約21,400 → Lv24
STR 27.1  VIT 22.0  END 13.6  AGI 10.0  DEX 10.0
```

1回のトレーニングでの成長は +0.03〜0.07 程度。
「1回では上がった気がしないが、半年続けると明らかに変わっている」速度に調整してあります。

### 係数を変えたあと

設定を変えても、**すでに保存された記録の EXP・成長量は変わりません**（記録時点の値が焼き込まれているため）。
過去の記録も新しい式で計算し直したい場合だけ、設定 →「メンテナンス」→「全記録を現在の設定で再計算」を実行してください（実行前に自動バックアップが作られます）。

## 5. ストリークの判定

- 記録がない日が **3日続く** とリセット（日数は設定で変更可）。
- つまり「中2日まで空けてOK」。
- 表示している日数は、継続チェーンの開始日から今日までの経過日数です（実際にトレした日数も併記）。
- ストリークが切れても、**累積EXP・Lv・ステータス・過去の記録は一切失われません**。

## 6. バックアップ

設定画面から:

- **データを書き出す** → `ore_dake_levelup_backup_YYYY-MM-DD.json`
- **データを読み込む** → 上記JSONを選んで復元（形式チェック → schemaVersion確認 → 必要なら migration → 整合性チェック）
- **自動バックアップの一覧** → migration・復元・初期化・再計算の直前に自動作成されたものから戻せる

機種変更のときは、書き出した JSON を新しい端末で読み込めばそのまま引き継げます。
